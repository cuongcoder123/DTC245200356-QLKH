CHƯƠNG 1: MỞ ĐẦU & TỔNG QUAN HỆ THỐNG

1.1. Đặt vấn đề & Mục tiêu Đề tài

Trong bối cảnh chuyển đổi số và sự bùng nổ của các ứng dụng thương mại điện tử, dịch vụ chuỗi cung ứng, khối lượng giao dịch và quản lý kho hàng tại các doanh nghiệp gia tăng theo cấp số nhân. Với phương pháp quản lý thủ công truyền thống qua sổ sách hoặc các ứng dụng đơn lẻ thiếu tính liên kết, bộ phận vận hành kho thường xuyên đối mặt với nguy cơ sai lệch tồn kho, chậm trễ trong xử lý đơn hàng và thiếu khả năng theo dõi trạng thái hệ thống theo thời gian thực. Đồng thời, việc đảm bảo tính an toàn, sẵn sàng và bảo mật cho hạ tầng ứng dụng quản lý kho đóng vai trò sống còn đối với hoạt động kinh doanh liên tục của doanh nghiệp.

Hệ thống Quản lý Kho hàng - Báo cáo Bài tập lớn Trang 2

Mục tiêu của đồ án này không chỉ dừng lại ở việc phát triển ứng dụng Web Quản lý kho hàng mà còn hướng tới triển khai theo mô hình Chuẩn vận hành hệ thống hiện đại (DevOps/SRE):

  • Đóng gói ứng dụng dạng Containerization bằng Docker & Docker Compose.
  • Cấu hình Nginx Reverse Proxy đóng vai trò gateway, xử lý HTTPS và thiết lập Security Headers.
  • Tích hợp bộ công cụ Giám sát chỉ số tài nguyên và dịch vụ (Prometheus + Grafana).
  • Tích hợp giải pháp Quản lý Log tập trung (Loki + Promtail) hỗ trợ truy vấn LogQL.
  • Áp dụng kỹ thuật Hardening hệ thống nhằm nâng cao tính an toàn và bảo mật.

1.2. Kiến trúc Tổng thể Hệ thống

Hệ thống được thiết kế theo mô hình kiến trúc phân tầng dịch vụ chuẩn mực (Multi-tier Architecture), đảm bảo tính cô lập, khả năng mở rộng linh hoạt và an toàn dữ liệu:

  1. User / Client Layer: Người dùng truy cập thông qua Trình duyệt Web bảo mật (HTTP/HTTPS).
  2. Reverse Proxy Layer: Nginx tiếp nhận các request, định tuyến tới Web App, phpMyAdmin, hoặc Grafana, đồng thời áp dụng mã hóa SSL/TLS và Security Headers.
  3. Application & Storage Layer:
    • Web Application (PHP / Node.js): Xử lý nghiệp vụ quản lý kho (Nhập/Xuất, Tồn kho, Nhà cung cấp).
    • Database (MySQL 8.0): Lưu trữ dữ liệu hệ thống kho hàng.
    • phpMyAdmin: Công cụ quản trị CSDL trực quan.
  4. Monitoring & Logging Layer:
    • Prometheus: Thu thập metrics định kỳ từ các Exporters (Node Exporter, cAdvisor, MySQL Exporter).
    • Grafana: Trực quan hóa metrics và logs thành các Dashboard theo dõi thời gian thực.
    • Promtail: Thu thập log file từ Nginx, App và MySQL, gửi về Loki.
    • Loki: Lưu trữ index log và phục vụ truy vấn LogQL.

3.1. Thiết kế Cơ sở Dữ liệu MySQL 8.0

Cơ sở dữ liệu inventory_db gồm 6 bảng chuẩn hóa quan hệ:

  1. users: Quản lý tài khoản, mã hóa mật khẩu BCRYPT, phân quyền admin và staff.
  2. categories: Danh mục phân loại sản phẩm trong kho hàng.
  3. suppliers: Thông tin đối tác, số điện thoại, email, địa chỉ giao dịch.

  5. inventory_transactions: Ghi nhận lịch sử Nhập kho (IMPORT) và Xuất kho (EXPORT).
  6. system_logs: Lưu vết nhật ký hoạt động hệ thống nội bộ.

CHƯƠNG 4: CẤU HÌNH NGINX REVERSE PROXY, SECURITY HEADERS & SSL (COMMIT 1)

4.1. Vai trò của Nginx Reverse Proxy

Nginx tiếp nhận kết nối ngoài tại cổng 80/443, tự động chuyển hướng HTTP sang HTTPS bằng mã phản hồi 301 Moved Permanently, quản lý tập trung chứng chỉ SSL/TLS và định tuyến: / vào Web App, /pma/ vào phpMyAdmin, /grafana/ vào Grafana.

4.2. Tạo SSL Certificate Tự ký (Self-Signed SSL)

openssl req -x509 -nodes -days 365 -newkey rsa:2048 \
  -keyout nginx/ssl/server.key -out nginx/ssl/server.crt \
  -subj "/C=VN/ST=Hanoi/L=Hanoi/O=DTC245200356/CN=localhost"
Hệ thống Quản lý Kho hàng - Báo cáo Bài tập lớn Trang 9

4.3. Thiết lập Security Headers trong default.conf

Nginx được trang bị đầy đủ 5 tiêu chuẩn Security Headers: X-Frame-Options "SAMEORIGIN" (chống Clickjacking), X-XSS-Protection "1; mode=block" (chống XSS), X-Content-Type-Options "nosniff" (chống MIME-sniffing), Referrer-Policy và Content-Security-Policy.

6.1. Nguyên lý Thu thập Log

Promtail gắn kết đọc trực tiếp từ /var/log/nginx/*.log (access/error log) và /var/log/app/*.log (JSON structured log), gắn nhãn (job="nginx", job="app") và đẩy về Loki qua API /loki/api/v1/push.

Hệ thống Quản lý Kho hàng - Báo cáo Bài tập lớn Trang 11

6.2. Ba Câu Truy Vấn LogQL Chuyên Sâu

Query 1: Lọc mã lỗi HTTP 4xx hoặc 5xx từ Nginx:

{job="nginx"} |= "status=" |~ "status=[45][0-9][0-9]"

Query 2: Thống kê tần suất request theo IP (Phát hiện tấn công DoS / Brute-force):

sum by (client_ip) (count_over_time({job="nginx"} [5m]))

Query 3: Truy vết lỗi giao dịch kho hàng (Inventory Transactions):

{job="app"} |= "inventory_transactions" |= "ERROR"

CHƯƠNG 7: ÁP DỤNG CÁC BIỆN PHÁP GIA CỐ BẢO MẬT (HARDENING) (YÊU CẦU 6)

  1. Non-Root User Trong Container: Web App chạy với người dùng hạn chế appuser (UID 1001), ngăn chặn rủi ro thoát container (Container Breakout).
  2. Phân Vùng Mạng (Network Isolation): Thiết lập 3 mạng Docker bridge độc lập (frontend-net, backend-net, monitoring-net). MySQL chỉ mở cổng nội bộ trong backend-net, không expose 3306 ra ngoài máy chủ Host.
  3. Quản Lý Mật Khẩu & Biến Môi Trường: Lưu trữ trong tệp .env riêng biệt, đưa vào .gitignore, cung cấp file mẫu .env.example phục vụ cộng tác an toàn.
  4. Giới Hạn Tài Nguyên (Resource Limits): Thiết lập CPU và RAM limit trong docker-compose.yml cho từng container, phòng chống cạn kiệt tài nguyên máy chủ.

CHƯƠNG 8: KIỂM THỬ HỆ THỐNG & ĐÁNH GIÁ THỰC NGHIỆM

8.1. Mục tiêu & Phương pháp Kiểm thử

Quá trình kiểm thử được triển khai đa tầng nhằm đánh giá thực nghiệm 4 trụ cột hệ thống: (1) Tính toàn vẹn nghiệp vụ kho và giao dịch ACID trên MySQL; (2) An toàn bảo mật cổng Nginx Gateway, mã hóa SSL/TLS và Security Headers; (3) Khả năng thu thập chỉ số Prometheus thời gian thực; (4) Khả năng gom log tập trung Promtail - Loki và độ chính xác của 3 câu truy vấn LogQL.

8.2. Bảng Ma trận Kiểm thử Thực nghiệm (Test Cases Matrix)

TC-06 Chuyển hướng HTTPS Gửi yêu cầu HTTP không mã hóa tới cổng 80/8080. Nginx trả về mã 301 Moved Permanently chuyển sang HTTPS. Chuyển hướng 100% lưu lượng sang https://localhost/. PASS
TC-07 HTTP Security Headers Kiểm tra Headers trả về từ Nginx Gateway qua curl -I. Đủ 5 headers: X-Frame, XSS, CSP, Nosniff, Referrer. Phản hồi 5/5 tiêu chuẩn an ninh chống Clickjacking/XSS. PASS
TC-08 Cô lập mạng MySQL Quét kết nối cổng 3306 từ máy chủ Host ngoài Docker. Cổng 3306 bị từ chối; chỉ mở nội bộ trong backend-net. MySQL cô lập an toàn tuyệt đối, không lộ port ngoài. PASS
TC-09 Prometheus Scrape Kiểm tra Scrape Targets chu kỳ 15s tại /prometheus/targets. 100% Exporter (mysql, node_exporter, prometheus) UP. 3/3 Exporter hoạt động ổn định, thu thập chỉ số liên tục. PASS
TC-10 Loki & 3 Truy vấn LogQL Sinh log lỗi giả lập (404, 500, lỗi xuất kho) và chạy LogQL. Promtail gom log tức thời; Loki lọc chính xác 3 câu query. Khớp 100% bản ghi lỗi HTTP và lỗi giao dịch kho hàng. PASS
Kết luận Đánh giá Thực nghiệm: Toàn bộ 10/10 ca kiểm thử (100%) đều đạt kết quả PASS. Hệ thống chứng minh khả năng vận hành ổn định, dữ liệu kho nhất quán theo chuẩn giao dịch ACID, hạ tầng mạng phân tầng bảo mật chặt chẽ và khả năng giám sát, truy vết lỗi (Observability) đạt độ tin cậy cao.

CHƯƠNG 9: KẾT LUẬN & HƯỚNG PHÁT TRIỂN

9.1. Kết quả Đạt được

  • Xây dựng hoàn chỉnh ứng dụng Web Quản lý Kho hàng đầy đủ tính năng nghiệp vụ, giao diện hiện đại, hỗ trợ in phiếu kho và xuất dữ liệu đối soát.
  • Triển khai thành công cụm 10 container dịch vụ hoạt động đồng bộ, an toàn bằng Docker Compose.
  • Nginx Reverse Proxy bảo vệ toàn diện với SSL tự ký và đầy đủ các HTTP Security Headers.
  • Hệ thống giám sát thời gian thực ổn định với Prometheus và Grafana Dashboards tự động nạp cấu hình.
  • Hệ thống gom log tập trung Loki + Promtail và thực thi chính xác 3 câu truy vấn LogQL nghiệp vụ.
  • Tuân thủ đầy đủ các chuẩn mực bảo mật hệ thống (Network Isolation, Non-root user, Resource limits) và quy trình Git chuyên nghiệp.

9.2. Hướng Phát triển Nâng cấp

  • Tích hợp đường ống CI/CD với GitHub Actions tự động kiểm thử và triển khai tự động.
  • Nâng cấp chứng chỉ SSL tự ký sang chứng chỉ Let's Encrypt với Certbot tự động gia hạn.
  • Mở rộng triển khai lên Kubernetes (K8s/K3s) hỗ trợ Auto-scaling và Self-healing.
